# Rust 1.98 Production and Laboratory Ledger

**Load when:** a design depends on toolchain APIs, target features, allocator
API, portable SIMD, or newly stabilized behavior.

**Output:** a stable-compatible implementation with explicit experimental
quarantine.

Every claim below was **empirically verified against rustc 1.98.0** on
2026-08-22 (compile probes, not memory). Re-verify at every toolchain bump.

## Pinning doctrine

The production language is **stable Rust 1.98.0, edition 2024** unless an
explicit architecture decision changes it. Classify every proposed API:

- **stable production** — available and supported on 1.98;
- **encapsulated compatibility** — capability built privately because the
  stable convenience API is absent (never downgrade the algorithm; wrap it);
- **nightly laboratory** — experiments/benchmarks only; never leaks into
  stable public contracts;
- **future candidate** — tracked without contaminating current architecture.

Never silently use a newer API. Never trust a nightly doc page as stability
evidence — probe the stable compiler.

## Stable production weapons (verified ✓)

- `core::hint::cold_path()` — measured rare-branch layout.
- `core::hint::select_unpredictable(cond, a, b)` — unpredictable cheap
  selection.
- `core::fmt::NumBuffer` + `<integer>::format_into(&mut NumBuffer)` —
  fixed-buffer integer formatting; removes formatting machinery and external
  itoa-style dependencies from hot paths.
- Algebraic float ops — `f32/f64::algebraic_add/sub/mul/div/rem` — permit
  reassociation/vectorization **under an explicit relaxed-numerics policy
  only** (see [05-simd.md](05-simd.md)).
- `str::substr_range` / `[T]::subslice_range` — recover offsets from
  subslices safely. **Caveat (verified):** they return the new
  `core::range::Range<usize>`, **not** `core::ops::Range` — convert
  explicitly where `ops::Range` is expected.
- Atomic view families — `Atomic*::from_mut`, `get_mut_slice`,
  `from_mut_slice` — phase transitions between exclusive plain data and
  atomic views without reallocation; synchronization semantics still require
  a full design.
- Strict provenance APIs — `ptr.addr()`, `with_addr`, `map_addr` — the
  default addressing model (see [04-unsafe.md](04-unsafe.md)).
- GATs; RPITIT/async-fn-in-trait (public-trait `Send`-bound caveat — see
  [09-concurrency.md](09-concurrency.md)); `MaybeUninit` +
  `spare_capacity_mut`; edition 2024 + resolver 3; workspace inheritance;
  PGO through rustc/LLVM.

## Nightly laboratory only (verified ✗ on stable 1.98)

- `std::simd` / portable SIMD (E0658) — `core::arch` intrinsics + SWAR are
  the stable lanes.
- Generic `allocator_api` for std owning types/collections.
- `Iterator::collect_into` (E0658) — use `Extend::extend`.
- `trim-paths` cargo profile key — rejected by cargo 1.98; do not add it.
- `generic_const_exprs`, trait aliases, type-alias impl Trait, const trait
  impls, dedicated `likely`/`unlikely` functions.

The laboratory may benchmark and prototype these; stable crates must compile
and function without them, and `nightly-lab` is never a transitive
requirement of normal crates.

## 1.98 audit notes

- `repr(transparent)` validity rules are stricter — genuine one-field ABI
  wrappers only.
- Runtime-symbol diagnostics are stronger — never accidentally export
  `memcpy`/`memset`/`strlen`-like names; audit `#[unsafe(no_mangle)]` and
  `export_name`.
- Rust 2024: `unsafe extern` blocks, `unsafe(...)` attribute forms,
  `unsafe_op_in_unsafe_fn` — all enforced by the workspace lint wall.

## Revision rule

Before changing the MSRV or adopting a newer compiler feature: re-probe the
stable/nightly classification empirically; re-audit unsafe/layout/provenance
notes; re-run representative codegen and benchmark comparisons; update this
ledger and its date; preserve stable RustX semantics unless an explicit
architecture decision changes them.
